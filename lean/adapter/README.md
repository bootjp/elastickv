# Mutation outcomes at the adapter boundary

Run `make lean-check` with the version in `lean/lean-toolchain` and Go. The check reads the current checkout. It fails if a selected predicate changes to an unsupported Go construct or if its decision differs from the Lean specification.

| Boundary | Property | Connection to the implementation |
| --- | --- | --- |
| Redis writes and EXEC | A lost decision stops retries and prevents reuse of an EXEC conflict attempt. This holds after any finite prefix of attempts. | `extract.go` translates the Go conditions and returns in the retry and reuse predicates. Lean proves their equivalence to `AdapterMutation.retry` and checks the EXEC guard. The Redis loop regression counts calls after leadership loss joined with a conflict. |
| DynamoDB and SQS transaction writes, S3 metadata writes | Uncertainty prevents the retry decision even when a conflict, lock or route fence is present. SQS receive also propagates uncertainty instead of skipping the message as a contention race. | The same source extraction covers the shared DynamoDB/SQS retry predicate and the S3 predicate. The conformance test calls the SQS receive predicate and all three dispatch normalizers. |
| Public gRPC RawKV and TransactionalKV mutations | An aborted projection requires a conflict with no uncertainty, lock, route fence or open circuit. Uncertainty takes priority over all of them. | The conformance test inspects the actual gRPC status and failure detail. For the same uncertain inputs it also checks the Redis reply and the DynamoDB, S3, SQS JSON and SQS Query responses. |
| Filesystem FUSE mutation barriers | A local inode barrier remains closed while its outstanding unknown count is positive, across any finite sequence of completions and resolutions. | `FuseMutationBarrier.lean` models the mutex-protected counter and sticky error in `internal/filesystem/fuseadapter/barrier.go`. Existing Go tests exercise multiple unknown operations on one inode, acknowledgement, and fsync. |

The extractor treats Go sentinel membership and the transport classifier as Boolean observations. Joined causes may set several bits at once. The executable conformance check crosses all 64 combinations of uncertainty, conflict, lock, fence, composed-route rejection and circuit-open with concrete Go errors. It includes both composed-route sentinels, leadership loss, cancellation, EOF, network errors and raw gRPC failures. The retry trace assumes the caller dispatches again only when the predicate allows it. A permitted retry can still require the caller to retain its previous write set or check deduplication evidence.

The FUSE model assumes serialized updates per inode, one resolution per acknowledged unknown operation, and an outstanding count that fits in uint64. Its theorem concerns the local barrier after preceding tickets complete. Storage durability, the origin of the coordinator's verdicts, crash recovery, reader linearizability, and operation-specific protocol semantics require separate arguments.
