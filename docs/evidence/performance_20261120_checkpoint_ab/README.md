# 1ページ版と2ページ版のsplit preflight比較

VM 150で4 reader・4 writerを走らせ、1ページ→2ページを3回繰り返した。preflight時間の観測上限が5秒以下だったのは1ページ版が1/3回、2ページ版が3/3回。全6試行でsplit完了・回復検証まで成功した。

| preflight区間の指標 | 1ページ | 2ページ | 変化 |
|---|---:|---:|---:|
| 時間の中央値（秒） | 5.210 | 4.550 | -12.7% |
| read p99（ms） | 4.323 | 4.496 | +4.0% |
| write p99（ms） | 25.717 | 25.580 | -0.5% |
| read 成功ops/s | 7,772.9 | 7,571.9 | -2.6% |
| write 成功ops/s | 291.2 | 278.4 | -4.4% |
| read 成功（3試行の累計件数） | 124,554 | 102,252 | |
| write 成功（3試行の累計件数） | 4,663 | 3,772 | |
| read エラー（3試行の累計件数） | 0 | 0 | |
| write エラー（3試行の累計件数） | 0 | 0 | |

各中央値は各版3試行の値から求めた。時間には、durableなFence未完了と完了witnessを10 ms周期で読み取った上下限の中点を用いた。p99は成功したRPCのレイテンシで、成功ops/sの分母は従来どおり100 ms観測のphase滞在時間。負荷はclosed-loopで、preflight期間が異なるため総成功件数も変わる。

|---:|---:|---:|---:|---:|---:|---:|
| 1 | 1 | 5.200–5.220 | 5.131 | 4.779 / 25.717 | 6,885.7 / 266.6 | 0 / 0 |
| 1 | 2 | 4.520–4.540 | 4.541 | 4.559 / 25.523 | 7,600.6 / 271.5 | 0 / 0 |
| 2 | 1 | 4.970–4.994 | 4.925 | 4.323 / 23.228 | 8,109.3 / 294.2 | 0 / 0 |
| 2 | 2 | 4.540–4.561 | 4.523 | 4.367 / 25.580 | 7,571.9 / 278.4 | 0 / 0 |
| 3 | 1 | 6.350–6.370 | 6.340 | 4.293 / 25.987 | 7,772.9 / 291.2 | 0 / 0 |
| 3 | 2 | 4.550–4.570 | 4.541 | 4.496 / 25.615 | 7,376.0 / 281.9 | 0 / 0 |

preflightを含むgroup間移動の全期間では、3試行合計のreadエラーが23,818→23,903件、writeエラーが1,110,105→1,133,927件だった。エラー0の集計区間はpreflight。全期間はphase滞在時間とclosed-loopの試行回数も変わる。

## 実行条件と再現

同じ8 vCPUのLinux VM、GOMAXPROCS=8、3 Raft nodes / 2 groups、source leaderはnode 0、target leaderはnode 1。各回は新規ストアを使用した。256キー×1 KiB、既定Sync、TLSとForward認証、profile無効。区間の前に同一groupのsplitを行い、続いてgroup間splitを実行した。全試行で移動後5経路×600件の書き込みと正規所有者からの読み返しを確認した。[runner](run-ab.sh)・[バイナリSHAと環境](environment.log)・[試行別の値](metrics.csv)

1ページ版と2ページ版の継続待ちはどちらも25 ms。2ページ版は2ページ分を仮進捗に保持し、元のjob・catalog version・実際に読んだsource routeに対するOCCで一度だけ確定する。次ページを開始できるtick内の時間予算は25 msから100 msへ変更した。この比較には集約、予算、保存直前の再検証の効果が含まれる。

厳密に同じ測定ソースを再構成するには、コミット `5ccfbc74a31f6b21aa4d631704ca922a0749c18e` の別々のcheckoutに一方のパッチを適用する。Go 1.27.3で `GOOS=linux GOARCH=amd64 CGO_ENABLED=0 go test -c -o one.test ./internal/server` を実行し、2ページ版は出力名を `two.test` にする。両方をrunnerと同じディレクトリに置いて `bash run-ab.sh` を実行する。[1ページの測定ソース](one.patch)・[2ページの測定ソース](two.patch)・[測定入力のSHA-256](provenance.json)

実装ブランチの1ページ比較元は `a8f582bda`、2ページ実装は `03cd340b7`。ブランチではlintに合わせてnamespace probeの並列数3を定数化し、probeエラーにstackを付けた。最終再検証のnamespace分岐も関数に切り出し、callerがadmissionの有無を明示する。計測は固定した上記パッチのバイナリで行った。

固定2ページ版のsplit回帰はテスト・サブテスト469件が成功した。実装ブランチでは全Goパッケージのテスト、対象のrace検査、リポジトリのlintが成功した。[固定版の回帰結果](two-regression-results.json)・[固定版に適用する回帰テスト](two-regression.patch)・[実装ブランチの検証結果](branch-checks.json)

各試行の `pair-*-{one,two}.log` にstdout、同名の `.exit` に終了コードを保存した。`python3 summarize.py` は全6試行の終了コード・leader配置・測定区間・p99・ops/s・移動後の各経路の成功件数を確認し、CSVを再生成する。
